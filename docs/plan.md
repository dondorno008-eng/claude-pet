## 1. Архитектура

Две части и один общий каталог между ними. Сокетов и портов нет.

```
 сессия Claude A ─ плагин ─┐                        ┌─ окно-лошадка (поверх всех окон)
 сессия Claude B ─ плагин ─┼─ ~/.claude-pet/ (0700) ─┤
 десктоп, вкладка Code ────┘   файлы JSON            └─ поле ввода по клику
```

Каталог `~/.claude-pet/` (Windows: `%USERPROFILE%\.claude-pet`):

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `sessions/<sessionId>.json` | плагин | статус, папка проекта, подпись сессии, время обновления |
| `inbox/<sessionId>.json` | оверлей (атомарной заменой) | `{id, text}` — один ожидающий промпт |
| `ack/<sessionId>.json` | плагин | `{id}` — промпт принят; оверлей после этого удаляет файл из inbox |
| `overlay.json` | оверлей | pid, версия, пульс |
| `config.json`, `packs/` | оверлей | положение, область, выбранный питомец, свои паки |

Почему файлы, а не сокет или порт: работает одинаково на macOS и Windows, не нужен токен, нет порта, в который может постучаться страница из браузера. Задержка до 1 секунды — для питомца нормально.

### 1.1 События сессии → оверлей

Плагин — один модуль хуков (function hooks), без правок `~/.claude/settings.json`.

| Статус лошадки | Событие мода | Статус доказательства |
|---|---|---|
| Работает | `turn.start` главного цикла | Подтверждено: событие есть; `agentId` «absent on the main loop» (TYPES:14983) — субагентов отсекаем |
| Готово | `turn.complete`, `reason: 'answer'` | Подтверждено: `TurnCompleteReason = 'answer' \| 'aborted' \| 'refusal' \| 'error'` (TYPES:14915) |
| Ошибка | `turn.complete`, `reason: 'error' \| 'refusal'` | Подтверждено там же |
| Ждёт человека | `classic.Notification` (`notification_type`, TYPES:7136–7140) | **Спайк S1/S2**: какие типы приходят и приходят ли они в десктопе |
| Сессия открылась / закрылась | `session.start`, `session.end` | Подтверждено: `session.start` «fires once when the session is ready» (REF:207); `SessionEndInput` (TYPES:12106) |

- Хуки только наблюдают: `void report(); return next(e)`. Ответа оверлея никто не ждёт — питомец вне цепочки подтверждений.
- `tool.check` и `classic.PermissionRequest` не трогаем: это гейты разрешений. Запасной вариант для «Ждёт человека», если `classic.Notification` не сработает, — прочитать вердикт `ask` из `tool.check`, не меняя его; решать по итогам спайка.
- Пульс: таймер `$.clock.every` раз в 15 с обновляет `sessions/<id>.json`; оверлей убирает сессии без пульса. Подтверждено: таймеры «run until cancelled or until the module reloads» (REF:207–211).
- Отсев одноразовых запусков (`claude -p`, SDK, ночные агенты владельца), чтобы лошадка их не показывала: по `e.isInteractive` (TYPES:12799) и `$.session.surfaces()` (TYPES:2970–2972). В десктопе `session.start` приходит с `surface: null` (TYPES:12793–12796 — «null for a -p run or the SDK»), поэтому точное правило отсева — **спайк S2**.

### 1.2 Промпт из оверлея → нужная сессия

Основной путь — `$.prompt.submit`:
- Подтверждено: «`$.prompt.submit` queues a prompt that starts a turn of its own once the session is idle (never folded into a running turn; ...), so background work can wake a quiet session» (REF:212).
- Подтверждено: `asUser: true` — «Submit the text as the person's own words, read bare without the "The <plugin> plugin sent a message" frame» (TYPES:9845).
- Подтверждено: вызов из таймера — штатный сценарий (REF:207–212).

Маршрутизация при нескольких сессиях:
- У каждой сессии свой экземпляр модуля и свой `sessionId` (`$.session.id()`); он читает только `inbox/<свой id>.json`.
- Плагин раз в секунду делает `$.fs.stat` своего inbox-файла; новый `id` → `$.prompt.submit({ text, asUser: true })` → пишет `ack`.
- Оверлей в поле ввода показывает выбор сессии: по умолчанию — последняя активная; если сессия одна — выбора нет. Подпись — имя папки проекта и начало последнего запроса.
- Сессия занята → промпт встаёт в очередь (поведение движка, см. цитату выше); лошадка показывает «в очереди».

Что закрыто, а что нет:
- Терминал Claude Code — путь документирован, проверка в S1.
- Десктоп, вкладка Code (локальная сессия) — мод грузится: «A mod installed from a terminal at the user scope loads in that local session too, and its `ui.render` hooks draw for the `desktop` surface» (REF:130). Виден ли там ход, запущенный через `$.prompt.submit`, — **спайк S2**.
- Обычный чат десктопного приложения (не Code) и облачные сессии — мода там нет, лошадка их не видит. Отсюда вопрос владельцу №2.

Альтернативы, если `$.prompt.submit` не подойдёт:
1. **Отдельный чат лошадки** — оверлей сам ведёт разговор через `claude -p` (или Agent SDK), ответ показывает в пузыре. Не зависит от открытых окон Claude, но это уже второй чат, а не «написать в свою сессию». Запасной продуктовый вариант.
2. **`claude -p --resume <id>`** — годится только когда сессия нигде не открыта (иначе два писателя в одну историю). Пригодится позже для режима «нет открытых сессий».
3. **`$.prompt.fill`** — кладёт текст в поле ввода, человек жмёт Enter сам. В десктопе не работает: «`isFilled: false` under a dialog or headless» (TYPES:3147–3150).
4. События `session.send` / `session.receive` (доставка между сессиями) — не изучены; смотреть, только если S1 провалится.

### 1.3 Как плагин запускает и держит оверлей

- Оверлей — обычное самостоятельное приложение, одно на всю машину (single instance), со своей галочкой «запускать при входе».
- Плагин его не сторожит. На `session.start` и не чаще раза в минуту на `turn.start`: если пульс в `overlay.json` устарел → `$.process.run(["open", "-g", <путь к .app>])` (Windows — запуск exe через `cmd /c start`). Повторный запуск уже работающего приложения — пустая операция.
- `$.process.spawn` не используем. Подтверждено: «leaving it, `return()` on the stream, `next.signal` aborting or the module unloading kills the child» (TYPES:3744) — закрытие одной сессии убивало бы общую лошадку.
- Подтверждено: `$.process.run` — запуск по argv без шелла, таймаут 30 с (TYPES:3721–3736).
- **Спайк S2:** работает ли `$.process.run` в сессии десктопа («CLI only», TYPES:3716). Если нет — оверлей стартует только сам (при входе в систему), плагин его не поднимает; на результат для пользователя это почти не влияет.
- Приложения нет на диске → одна подсказка `$.ui.toast` «Лошадка не установлена — /pet install».

### 4.4 Безопасность

- **Локальный канал.** TCP-порта нет вообще — значит, нет и атаки со страницы в браузере (главная дыра клонов с портом без токена). Каталог `~/.claude-pet` с правами 0700. Токен на файловом канале ничего не добавляет: писать туда может только процесс того же пользователя, а он и так может править `~/.claude`. Правило на будущее: если когда-нибудь появится сокет или порт — только с токеном.
- **Что может прийти в сессию:** только текст из `inbox/<свой id>.json`, с ограничением длины. Промпт попадает в сессию с её текущим режимом разрешений — как если бы человек набрал его сам.
- **Питомец вне цепочки подтверждений:** ни одного гейтящего хука, ни одного ожидания ответа оверлея.
- **Телеметрии нет.** Сеть используется один раз — скачать релиз в `/pet install`. Оверлей в сеть не ходит.
- **Без патча бинарника и без accountUuid:** `$.session.identity()` не вызываем.
- **Бэкап и удаление.** Мод не правит `settings.json` (в отличие от клонов на классических хуках), бэкапить нечего. Удаление: `/pet uninstall` (закрыть лошадку, убрать приложение и `~/.claude-pet`) + удалить мод.
- **Хрупкость API.** «The API is early access and moves between releases» (REF:5). Мод держим тонким (порядка 150 строк), минимальную версию Claude Code фиксируем по итогам S1.

## 6. Вопросы владельцу

1. **На чём работает Настя — Mac или Windows?**
   Сейчас всё проверяется на Mac. Mac — MVP идёт по плану. Windows — нужен её компьютер или виртуалка для проверки, MVP сдвигается.
   Рекомендация: начать с Mac; если у неё Windows — сказать сейчас.

   1б. **Ноутбук Насти рабочий (с корпоративной защитой) или личный?**
   На рабочем неподписанное приложение и сам мод могут быть заблокированы политиками.
   Рекомендация: если рабочий — попросить её проверить, ставятся ли у неё плагины в Claude Code, до начала диалога 2.

2. **Где Настя пишет Claude: терминал, вкладка Code в приложении или обычный чат приложения?**
   Мод живёт только в Claude Code (терминал и вкладка Code). В обычном чате его нет — лошадка не увидит эти разговоры и не сможет в них писать.
   Рекомендация: если обычный чат — делать «отдельный чат лошадки» (она сама разговаривает с Claude, ответ в пузыре); это другой MVP, на одну-две сессии длиннее.

3. **Репозиторий публичный или приватный, и под каким аккаунтом?**
   Публичный: любой ставит одной строкой, сборки на GitHub бесплатны. Приватный: ставят только приглашённые, у каждого должен быть настроен GitHub; минуты сборки под macOS платные.
   Рекомендация: публичный, под личным аккаунтом (сейчас `gh` вошёл как `dondorno008-eng` — подтвердить, что это он). Секретов в репозитории не будет.

4. **Покупать Apple Developer (~99 $ в год)?**
   Без него: установка через `/pet install` идёт без предупреждений, но скачивание из браузера macOS блокирует.
   Рекомендация: сейчас не покупать; вернуться к вопросу перед широкой раздачей.

5. **Разрешить на 30–60 минут поставить тестовый мод на вашу машину (ворота G1)?**
   Иначе нельзя проверить вкладку Code десктопа. Мод на это время загрузится во все ваши сессии, но он только пишет файл состояния; после проверки снимается одной командой.
   Рекомендация: да, в тихое окно без ночных прогонов.

Решения по умолчанию (менять можно в любой момент, вопроса не требуют): графика — сгенерированная и вычищенная вручную, без платного художника; стек — Tauri 2; локальный путь — `~/Documents/claude-pet`; название на GitHub — нейтральное или `claude-pet`, решается при создании.
