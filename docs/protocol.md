# Протокол «мод ↔ окно-лошадка» (v1)

Каталог `~/.claude-pet/` (права 0700, файлы 0600). Сокетов и портов нет. Все файлы — JSON в UTF-8, у каждого поле `v: 1`.
Писатель каждого файла один; читатель терпит недописанный файл (просто пропускает чтение до следующего раза).

| Файл | Пишет | Читает | Когда |
|---|---|---|---|
| `sessions/<sessionId>.json` | мод (одна сессия Claude = один файл) | окно | на каждом событии сессии + пульс раз в 15 с |
| `inbox/<sessionId>.json` | окно, атомарно (tmp + rename) | мод, раз в 1 с | человек отправил промпт |
| `acks/<sessionId>.json` | мод | окно | мод принял промпт / ход начался / ошибка |
| `overlay.json` | окно | мод | при старте окна и раз в 15 с |

## sessions/&lt;sessionId&gt;.json

```json
{ "v": 1, "sessionId": "…", "cwd": "/Users/n/proj", "project": "proj",
  "title": "Найди последние новости", "status": "running", "step": "Чтение plan.md",
  "startedAt": 1762950000000, "updatedAt": 1762950012000, "pulseAt": 1762950010000,
  "doneAt": null, "continuedFrom": null, "continuedAs": null }
```

- `status`: `ready` — сессия свободна; `running` — идёт ход; `needs-input` — ждёт ответа человека (диалог разрешения);
  `blocked` — ход кончился ошибкой или отказом; `ended` — сессия закрыта.
- `step` — человеческая строка текущего шага («Размышление…», «Чтение X», «Правка X», «Выполняет команду…»,
  «Ищет в проекте…», «Ждёт вашего ответа»), `null` вне хода.
- `title` — начало первого промпта сессии (название сессии движок моду не отдаёт).
- `doneAt` — время последнего успешного конца хода (для статуса «Готово»).
- После `/clear` id сессии меняется: старый файл получает `status: ended, continuedAs: <новый id>`,
  новый — `continuedFrom: <старый id>`. Окно идёт по цепочке.
- Времена — миллисекунды Unix.

Живая сессия: `status != ended` и `max(updatedAt, pulseAt)` не старше 45 с. Окно удаляет файлы сессий, которые
мертвы больше суток (мод удалять не умеет — у `$.fs` нет удаления).

## inbox/&lt;sessionId&gt;.json

```json
{ "v": 1, "id": "c0ffee-…", "text": "Найди последние новости", "newChat": false, "createdAt": 1762950020000 }
```

- Один ожидающий промпт на сессию. `id` — уникальный (UUID). `text` — 1…8000 символов.
- `newChat: true` — мод сначала делает `/clear` (новый чат в том же окне), потом подаёт текст.
- Окно удаляет файл, когда в `acks/` появился тот же `id` (при `newChat` ack приходит в файл НОВОГО id, с `from`).

## acks/&lt;sessionId&gt;.json

```json
{ "v": 1, "id": "c0ffee-…", "status": "started", "queuedAt": 1762950021000, "startedAt": 1762950021500 }
```

- `status`: `queued` (принят, ждёт конца идущего хода) → `started` (ход начался) или `failed` (+ `error`).
- `from` — id старой сессии, если промпт пришёл с `newChat`.
- Мод не подаёт `id`, совпадающий с последним ack — это защита от повтора, пока окно не удалило inbox-файл.

## overlay.json

```json
{ "v": 1, "pid": 4242, "version": "0.1.0", "pulseAt": 1762950015000 }
```

Мод запускает окно (`open -g -a Лошадка`), если пульса нет дольше 60 с; повторный запуск идущего окна — пустая операция.

## Статус лошадки

Над всеми живыми сессиями, по приоритету: **ждёт** (`needs-input`) > **ошибка** (`blocked`) > **готово**
(`ready` и `doneAt` не старше 5 мин) > **работает** (`running`) > **отдыхает**.
Карточка показывает сессию, в которую человек писал последним, иначе — самую свежую по `updatedAt`.

Проверка примеров: `node fixtures/check.mjs` (форматы файлов из `fixtures/` и приоритет статусов).
