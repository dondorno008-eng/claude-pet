# Протокол «мод ↔ окно-лошадка» (v1)

Каталог `~/.claude-pet/` (права 0700, файлы 0600). Сокетов и портов нет. Все файлы — JSON в UTF-8, у каждого поле `v: 1`.
Писатель каждого файла один; читатель терпит недописанный файл (просто пропускает чтение до следующего раза).

| Файл | Пишет | Читает | Когда |
|---|---|---|---|
| `sessions/<sessionId>.json` | мод (одна сессия Claude = один файл) | окно | на каждом событии сессии + пульс раз в 15 с |
| `inbox/<sessionId>.json` | окно, атомарно (tmp + rename) | мод, раз в 1 с | человек отправил промпт |
| `acks/<sessionId>.json` | мод | окно | мод принял промпт / ход начался / ошибка |
| `overlay.json` | окно | мод | при старте окна и раз в 15 с |
| `show.json` | мод | окно | человек набрал `/horse` |

## sessions/&lt;sessionId&gt;.json

```json
{ "v": 1, "sessionId": "…", "cwd": "/Users/n/proj", "project": "proj",
  "title": "Найди последние новости", "status": "running", "step": "Чтение plan.md",
  "startedAt": 1762950000000, "updatedAt": 1762950012000, "pulseAt": 1762950010000,
  "doneAt": null, "continuedFrom": null, "continuedAs": null }
```

- `status`: `ready` — сессия свободна; `running` — идёт ход; `needs-input` — ждёт ответа человека (диалог разрешения);
  `blocked` — ход кончился ошибкой или отказом; `ended` — сессия закрыта.
- `step` — человеческая строка текущего шага («Размышление…», «Чтение X», «Правка X», «Выполняет команду…»,
  «Ищет в проекте…», «Ждёт вашего ответа»), `null` вне хода.
- `title` — начало первого промпта сессии (название сессии движок моду не отдаёт).
- `doneAt` — время последнего успешного конца хода (для статуса «Готово»).
- `stoppedAt` — время последнего хода, прерванного кнопкой ■ (статус после него — `ready`).
- `answer` — текст ответа Claude в последнем законченном ходе (до 6000 символов); `null`, пока идёт ход.
  Карточка показывает его под строкой «Готово» и не сворачивается сама, пока ответ на экране.
- После `/clear` id сессии меняется: старый файл получает `status: ended, continuedAs: <новый id>`,
  новый — `continuedFrom: <старый id>`. Окно идёт по цепочке.
- Времена — миллисекунды Unix.

Живая сессия: `status != ended` и `max(updatedAt, pulseAt)` не старше 45 с. Окно удаляет файлы сессий, которые
мертвы больше суток (мод удалять не умеет — у `$.fs` нет удаления).

## inbox/&lt;sessionId&gt;.json

```json
{ "v": 1, "id": "c0ffee-…", "text": "Найди последние новости", "newChat": false, "createdAt": 1762950020000 }
```

- Один ожидающий промпт на сессию. `id` — уникальный (UUID). `text` — 1…8000 символов.
- `newChat: true` — мод сначала делает `/clear` (новый чат в том же окне), потом подаёт текст.
- Стоп: `{ "v": 1, "id": "…", "stop": true, "createdAt": … }` без `text` — мод прерывает идущий ход (`$.turn.abort`);
  если хода нет, сразу пишет ack `stopped`.
- Окно удаляет файл, когда в `acks/` появился тот же `id` (при `newChat` ack приходит в файл НОВОГО id, с `from`).

## acks/&lt;sessionId&gt;.json

```json
{ "v": 1, "id": "c0ffee-…", "status": "started", "queuedAt": 1762950021000, "startedAt": 1762950021500 }
```

- `status`: `queued` (принят, ждёт конца идущего хода) → `started` (ход начался) или `failed` (+ `error`);
  на стоп — `stopped` (+ `stoppedAt`) или `failed`.
- `from` — id старой сессии, если промпт пришёл с `newChat`.
- Мод не подаёт `id`, совпадающий с последним ack — это защита от повтора, пока окно не удалило inbox-файл.

## overlay.json

```json
{ "v": 1, "pid": 4242, "version": "0.1.0", "pulseAt": 1762950015000 }
```

Мод запускает окно (`open -g -a Лошадка`), если пульса нет дольше 60 с; повторный запуск идущего окна — пустая операция.

## show.json

```json
{ "v": 1, "at": 1762950030000 }
```

`/horse` в любой сессии пишет новый `at` и запускает окно, если его нет. Окно на новый `at` показывается
(даже спрятанное ✕) и открывает строку ввода. Свежий `at` (моложе 15 с) при старте окна тоже считается.

## Возврат и карточки

- ⌃⌥Пробел — глобальная клавиша окна: спрятана → вернуть со строкой; строка открыта → свернуть; иначе → строка.
- Каждый отправленный промпт — карточка под лошадью (до 3, свежие сверху, хранятся в `localStorage`):
  заголовок = текст промпта, строка шага из `sessions/`, ↩ — дописать в тот же чат, ■ — стоп, × — убрать.
  Карточки видны, пока задача работает или ждёт; через 12 с после конца стопка сворачивается.
- ↗ или клик по названию (когда ход закончен) — открыть чат в приложении Claude: там весь ответ и можно писать
  дальше. Окно зовёт `claude stop <короткий id>` (для фонового чата: у сессии один писатель), потом
  `open "claude://resume?session=<id>"` — десктоп добавляет чат в боковую панель. Карточка после этого убирается.

## Новый чат (по умолчанию, кнопка «+» включена)

- Enter в строке → окно запускает `claude --bg -- <текст>` в папке выбранной сессии (без `.claude/worktrees/…`;
  нет выбранной — домашняя папка). Окно Claude не открывается; чат идёт в фоне, в боковой панели десктопа его нет
  (`claude agents` — список, `claude stop <id>` — остановить). CLI печатает `backgrounded · <короткий id>`.
- Мод загружается и в фоновом чате, поэтому пишет `sessions/<id>.json` и читает `inbox/` как в любой сессии.
- Карточка находит свой чат по `sessions/`: `sessionId` начинается с короткого id; запасной путь — `startedAt ≥
  отправка − 2 с`, без `continuedFrom`, заголовок или `lastPrompt` начинается с первых 40 символов текста.
  Дальше — как обычная карточка (↩ ■). Не нашлась за 2 мин — серая «Новый чат не запустился».
- CLI отказал (например, «Workspace not trusted» — папку ни разу не открывали в `claude`) → красная карточка
  «Не запустилось: <первая строка ответа CLI>».
- «+» выключен → старый путь: `inbox/` в выбранную сессию.

## Поза лошадки

Позу задаёт только человек, сессии Claude её не меняют: покой — лежит; тащат мышью — скачет; открыта строка
ввода (клик по лошади, ⌃⌥Пробел, `/horse`) — стоит. Сама по экрану не ходит. Кнопки ✎ ✕ (и ˅ при карточках) —
только под мышкой. Карточки — только запросы, отправленные из лошадки; чужие сессии карточек не создают.

Проверка примеров: `node fixtures/check.mjs` (форматы файлов из `fixtures/` и правила карточек).
